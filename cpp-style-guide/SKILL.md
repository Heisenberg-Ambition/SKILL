# C++ 代码风格与审查规则

> 用途: 作为 C++ 代码生成, 修改, 重构和审查的默认规则.
> 基线: Google C++ Style Guide 常用约定 + C++ Core Guidelines 共识 + 项目命名 profile + 工程可维护性.
> 标准: 不固定任何 C++ 标准版本. 语言标准由项目构建配置, 现有代码和 CI 决定.
> 优先级: 正确性 > 可读性 > 性能; 一致性 > 个人偏好.
> 冲突处理: 项目规范 > 团队约定 > 本文件 > 个人偏好.

## 使用流程

1. 先读取项目构建配置, 现有代码, 命名习惯和格式化配置.
2. 不擅自新增或修改语言标准, 编译器选项, 语言扩展和构建模式.
3. 新代码与周围代码保持一致; 只有明确收益时才做局部现代化.
4. 生成代码后按本文末尾清单自检; 审查代码时只报告有依据的问题.
5. 无法确认语言标准时, 使用项目现有代码已经使用的特性, 并明确说明假设.

## 规则标记

- **[必须]** 强制遵守.
- **[推荐]** 默认采纳, 有明确理由时可例外.
- **[避免]** 不应出现, 除非维护旧接口或存在可验证的必要性.
- **[Google]** Google C++ Style Guide 常用约定, 项目可以覆盖.
- **[版本相关]** 仅在项目语言标准支持时使用, 必须提供回退方案.
- **[项目约定]** 由项目自行选择, 但同一项目内必须统一.

## 1. 语言标准, 构建与可移植性

1.1 **[必须]** 不假定 C++ 标准版本, 不在规则或示例中硬编码 `-std=c++XX`. 以 `CMakeLists.txt`, `compile_commands.json`, 构建脚本, CI 和现有代码为准.

1.2 **[必须]** 代码不得使用高于项目标准的语言或库特性. 无法确认标准时, 优先使用项目已有代码普遍使用的特性.

1.3 **[版本相关]** 使用受标准版本限制的特性时, 通过特性测试宏, 构建配置或项目抽象层隔离, 并提供可编译的回退路径. 不要依赖编译器私有扩展模拟标准特性.

1.4 **[必须]** 开启常规警告, GCC/Clang 至少使用 `-Wall -Wextra -Wpedantic`; CI 推荐 `-Werror`. 警告必须在提交前处理, 不得用大范围抑制掩盖问题.

1.5 **[必须]** 禁止非标准编译器扩展. 平台相关代码隔离到独立文件, 使用明确的平台宏保护, 不污染公共接口.

1.6 **[必须]** 同一目标, 公共头文件和链接库必须使用一致的语言标准与 ABI 配置. 不混用不同标准编译的公共类型和接口.

1.7 **[必须]** 不依赖未定义行为, 实现定义行为或未指定的求值顺序. 需要依赖实现行为时, 使用 `static_assert` 或运行时检查明确约束.

## 2. 头文件与作用域

2.1 **[必须]** 头文件必须自包含, 可被单独编译. 头文件使用 `.h`, 源文件使用 `.cc`; `.inc` 仅用于确实需要文本包含且不可独立编译的场景.

2.2 **[必须]** 头文件使用 include guard 或 `#pragma once`, 同一项目只能选择一种. Google 风格 guard 基于完整路径, 例如 `PROJECT_PATH_FILE_H_`.

2.3 **[必须]** 遵循 Include What You Use. 使用某符号就直接包含定义它的头文件, 不依赖其他头文件的传递包含.

2.4 **[必须]** `#include` 顺序为: 对应头文件, C 系统头, C++ 标准库头, 其他库头, 本项目头. 各组之间空一行, 组内按字母排序. 项目头使用相对源码根的路径.

2.5 **[必须]** 减少不必要 include, 但不得前向声明 `std` 或第三方库实体. 只前向声明本项目类型; 需要完整类型时直接包含头文件.

2.6 **[必须]** 非 `inline` 和非模板实现放在 `.cc` 中. 头文件中的短内联函数应控制在约 10 行以内, 并保持 ODR 安全.

2.7 **[必须]** 除明确例外, 代码放入项目命名空间. 禁止 `using namespace`; 禁止 inline namespace. 命名空间名使用项目名加必要路径, 避免过深嵌套.

2.8 **[必须]** 源文件中仅供内部使用的定义放入匿名命名空间或使用内部链接, 不在头文件中这样做. 匿名命名空间结束注释写为 `}  // namespace`.

2.9 **[必须]** 不向 `std` 命名空间添加声明, 除非标准明确允许对用户类型进行特化.

2.10 **[推荐]** 局部变量尽量靠近首次使用处声明并初始化, 缩小作用域. 循环变量在循环语句内声明; 仅当构造开销明显且语义正确时才提到循环外.

2.11 **[Google]** 避免具有非平凡析构的静态存储期对象. 优先 `constexpr`; 标准支持时使用 `constinit` 保证常量初始化. 禁止静态智能指针和依赖动态初始化的全局容器.

2.12 **[版本相关]** 类或命名空间作用域的 `thread_local` 应使用常量初始化. 注意线程退出时析构顺序和 use-after-free 风险, 优先使用平凡类型.

## 3. 资源管理与 RAII

3.1 **[必须]** 优先值语义和 RAII. 所有权层级为: 栈对象, `std::unique_ptr`, `std::shared_ptr`. `std::shared_ptr` 只用于真实共享所有权, 不作为默认生命周期工具.

3.2 **[必须]** 避免裸 `new` / `delete`; 优先容器, 智能指针和 RAII 包装器. 裸指针仅用于非拥有观察或必须可为空的接口.

3.3 **[必须]** 优先 `std::make_unique` / `std::make_shared`, 不在业务代码中散落显式 `new`. 标准不支持 `make_unique` 时封装项目内的 `MakeUnique` 工厂. 不使用 `std::auto_ptr`.

3.4 **[必须]** 不要让同一裸指针构造多个智能指针. 共享所有权优先使用 `std::shared_ptr<const T>` 表达不可变对象; 循环引用用 `std::weak_ptr` 打破.

3.5 **[必须]** 传递所有权时按值传 `std::unique_ptr`; 借用时传 `T&`, `const T&` 或 `T*`. 只有需要参与共享所有权时才按值传 `std::shared_ptr`; 不要仅为了避免引用计数而长期使用 `const std::shared_ptr<T>&`.

3.6 **[必须]** 优先 Rule of Zero. 若手写析构, 拷贝构造, 拷贝赋值, 移动构造或移动赋值中的任何一个, 必须明确整套特殊成员函数的语义.

3.7 **[必须]** 声明析构函数会抑制隐式移动操作. 需要移动语义时显式声明移动构造和移动赋值; 移动操作应 `noexcept`, 并在移动后保持源对象有效可析构.

3.8 **[必须]** 不要 `return std::move(local)`, 这会阻止返回值优化. 不返回局部对象的引用或指针. 返回动态所有权时使用智能指针, 不用裸指针.

3.9 **[必须]** 用 `{}` 初始化防止窄化, 并注意 `std::initializer_list` 的优先级. 成员按声明顺序在构造初始化列表中初始化, 避免在构造函数体内赋值.

3.10 **[必须]** 多态基类析构函数应为 `virtual`, 或使用 protected 非虚析构禁止通过基类删除. 构造和析构过程中不调用虚函数.

3.11 **[推荐]** 构造函数保持简单, 不执行可能失败且无法报告的复杂初始化. 需要失败处理时使用工厂函数或明确的 `Init` 流程, 避免半构造对象.

3.12 **[推荐]** 小对象和局部对象优先栈分配. 让对象拥有对象, 而不是让对象拥有指针.

3.13 **[版本相关]** 用 `std::optional<T>` 表示可能缺失的值, 用 `std::variant` 表示封闭类型集合, 用 `std::any` 仅处理真正开放的动态类型. 不用 `optional` 表示错误细节.

3.14 **[版本相关]** 用 `std::string_view` 作为只读字符串参数, 不长期存储, 不从临时 `std::string` 构造后继续持有.

3.15 **[版本相关]** 数值和字符串转换优先 `<charconv>`; 简单转换使用 `std::stoi` 时必须处理异常和越界. 时间使用 `<chrono>`, 随机数使用 `<random>`, 路径优先 `std::filesystem`, 不可用时使用项目路径抽象.

3.16 **[推荐]** 简单匹配不用 `std::regex`; 优先字符串查找或明确的手写解析. 固定种子的随机测试必须显式记录种子.

3.17 **[必须]** `std::move` 只把表达式转换为右值引用, `std::forward` 只按模板参数保持值类别. 真正的移动或转发发生在后续构造, 赋值或函数调用中.

3.18 **[必须]** 右值可以绑定到 `const T&`. 若没有 `T&&` 重载, `T(std::move(value))` 仍可能调用拷贝构造. 不要假设写了 `std::move` 就一定发生移动.

3.19 **[推荐]** 不滥用引用成员. 可空或可重新绑定时使用指针; 表达所有权时使用智能指针; 引用成员应保证生命周期清晰.

3.20 **[必须]** 内置类型必须初始化. 数值, 指针和枚举不得处于未初始化状态.

3.21 **[推荐]** 循环内创建的独立对象应尽量在循环内构造. 只有所有权确实转移且源对象不再使用时才 `std::move`; 不要在循环外复用对象后无条件移动.

3.22 **[版本相关]** 表达原始字节时优先 `std::byte`. 标准不支持时使用 `unsigned char` 或项目已有的字节类型, 不用普通 `char` 表达字节语义.

## 4. 类, 接口与 const

4.1 **[必须]** 能加 `const` 就加; 不修改对象状态的成员函数标 `const`. `const` 成员函数不自动线程安全.

4.2 **[必须]** 成员数据默认 `private`; 暴露行为而不是数据. getter 按需提供, setter 谨慎提供.

4.3 **[Google]** `struct` 仅用于被动数据载体, 字段全部 public 且不存在跨字段不变量. 其他类型使用 `class`. 无状态 traits 和模板元函数可以使用 `struct`.

4.4 **[必须]** 单参数构造函数和转换运算符标 `explicit`, 除非有意支持隐式转换. 拷贝构造, 移动构造和单 `initializer_list` 构造按语言规则处理, 不错误添加 `explicit`.

4.5 **[必须]** 派生类覆盖虚函数标 `override`, 不重复写 `virtual`; 禁止继续覆盖时标 `final`.

4.6 **[必须]** 用 `= delete` 禁用函数, 用 `= default` 显式默认. 不用未定义的 private 声明表达禁用.

4.7 **[必须]** 区分名字隐藏, 重载和覆盖:

- 名字隐藏: 派生类同名函数隐藏基类所有同名重载.
- 重载: 同一作用域中函数名相同, 参数列表不同.
- 覆盖: 基类虚函数且完整签名匹配, 运行时多态.

需要保留基类重载时使用 `using Base::function;`.

4.8 **[必须]** 不重新定义继承而来的非虚函数. public 继承必须建模 is-a; 组合优于继承; 多重继承仅用于接口组合, 避免多实现继承和菱形继承.

4.9 **[推荐]** 接口类使用纯虚函数加虚析构, 或 protected 非虚析构. 基类尽量抽象, 避免从具体类派生导致切片.

4.10 **[必须]** 在公共 API 中明确类型是否可拷贝和可移动. 可拷贝类型成对声明拷贝构造和拷贝赋值; 仅移动类型声明移动操作并删除拷贝; 不可拷贝不可移动类型显式删除相关操作.

4.11 **[推荐]** 成员函数按需标 `const`, `noexcept`, `override`, `final`, `= 0`, `&` 或 `&&`. `volatile` 仅用于特殊硬件或底层场景, 不用于并发同步.

4.12 **[必须]** `noexcept` 是强承诺. 标记为 `noexcept` 的函数一旦抛出异常, 程序直接 `std::terminate`; 析构函数不得抛出异常.

4.13 **[推荐]** 函数参数规则:

- 小对象, 内置类型, 迭代器, 函数对象和小型可平凡复制类型通常按值传递.
- 大对象只读传 `const T&`.
- 非可选输出参数传引用.
- 可选输出或输入输出参数传非 const 指针.
- 所有纯输入参数放在输出参数之前.

4.14 **[必须]** 比较器, 哈希和回调保持语义一致. 重载运算符必须有直观语义, 并与内置类型行为一致. 定义相等比较时同时提供一致的 `operator==`; 标准支持时再考虑 `operator<=>`.

4.15 **[必须]** 不重载 `&&`, `||`, `,` 或一元 `&`. 不定义用户自定义字面量. 二元非修改运算符优先定义为非成员函数.

4.16 **[版本相关]** 属性按语义使用: `[[maybe_unused]]` 标记确实未使用的实体, `[[fallthrough]]` 标记故意贯穿, `[[deprecated]]` 标记废弃接口, `[[noreturn]]` 标记不返回函数.

4.17 **[必须]** `switch` 用于离散值分派, `if/else` 用于条件判断. `switch` 分支以 `break`, `return` 或 `[[fallthrough]]` 结束. 覆盖全部枚举值时可不写 `default`; 否则必须处理 `default`. 分支多且映射稳定时使用表驱动, 函数指针数组或 `constexpr` 映射.

4.18 **[推荐]** 用 `static_assert` 做编译期约束. 标准支持时用 `if constexpr` 简化模板分支, 但不替代运行时分派.

4.19 **[Google]** 类声明顺序为 `public:`, `protected:`, `private:`. 段内顺序为类型和别名, 数据成员, 静态常量, 工厂函数, 构造和赋值, 析构, 其他函数, 其他数据成员.

4.20 **[推荐]** 优先命名空间中的非成员非友元函数, 减少不必要的成员函数. 需要静态多态时可考虑 CRTP, 但避免复杂模板继承层次.

4.21 **[推荐]** 避免不必要的模板元编程. 模板定义放在头文件并保持 ODR 安全; 所有实例化都局限在单一源文件时, 可使用显式实例化把定义移出公共头文件.

## 5. 函数设计

5.1 **[推荐]** 函数保持短小, 单一职责. 超过约 40 行时考虑拆分; 参数过多时考虑聚合为有语义的结构体.

5.2 **[推荐]** 优先使用返回值表达结果, 少用输出参数. 返回值优于返回裸指针; 裸指针仅用于可空或非拥有观察.

5.3 **[必须]** 参数顺序保持一致: 纯输入参数在前, 输出和输入输出参数在后. 调用点应能辨认输出参数.

5.4 **[Google]** 虚函数不使用默认参数. 默认参数的值不得依赖求值时机或副作用; 可读性更好时优先使用重载.

5.5 **[推荐]** 仅当调用点无需查看声明就能理解行为时使用重载. 重载集合应有统一的 umbrella 注释.

5.6 **[推荐]** 常规函数使用前置返回类型. 尾置返回类型仅用于 lambda, 复杂模板或明显更易读的场景.

5.7 **[必须]** 不返回局部对象的引用或指针. 不返回指向已销毁临时对象的 `std::string_view`, `std::span` 或其他视图.

5.8 **[推荐]** 前置条件检查使用 early return; 对等的二选一逻辑使用对称 `if/else`. 错误分支尽早退出, 减少嵌套.

5.9 **[推荐]** 复杂条件提取为具名布尔变量. 不在条件表达式中写多副作用或难以理解的赋值. 布尔表达式混用多种运算符时使用括号明确优先级.

5.10 **[推荐]** 一般使用前置自增 `++i`; 只有确实需要旧值时才使用后置自增. 数值累加或更新使用 `+=` 等复合赋值, 只要它比 `i = i + n` 更清楚.

5.11 **[推荐]** 一般不写 `this->`, 除非存在名字遮蔽, 依赖模板基类成员或明确需要强调当前对象.

## 6. 类型, 初始化与转换

6.1 **[推荐]** 类型从初始化式明显可见时使用 `auto`; 公共接口, 所有权和数值语义处写明确类型. 使用 `auto&` / `auto&&` 时明确值类别和生命周期.

6.2 **[推荐]** 用 `enum class` 替代无作用域 `enum`; 用 `using` 别名替代 `typedef`.

6.3 **[Google]** 常规整数使用 `int`; 需要固定宽度, 二进制布局或协议字段时使用 `<cstdint>` 类型. 无符号类型仅用于位模式或明确依赖模运算的场景.

6.4 **[必须]** 避免有符号和无符号之间的隐式混用. 比较和算术前统一类型, 不使用强制转换掩盖负值或溢出问题.

6.5 **[推荐]** 默认使用 `double`; 只有明确需要节省空间或接口要求时使用 `float`. 浮点比较使用容差或 `std::numeric_limits`, 不直接比较相等.

6.6 **[必须]** 不用 C 风格强制转换. 优先 `static_cast`; `dynamic_cast`, `reinterpret_cast`, `const_cast` 审慎使用并局部化.

6.7 **[必须]** 用 `nullptr` 表示空指针, 不用 `NULL` 或 `0`.

6.8 **[必须]** `reinterpret_cast` 仅用于底层字节或硬件接口. 类型双关使用 `std::memcpy` 或标准提供的字节表示工具.

6.9 **[必须]** `const_cast` 仅用于适配不修改对象的旧接口. 不修改原本声明为 const 的对象.

6.10 **[推荐]** 能在编译期完成的计算不要在运行期重复. 标准支持时使用 `constexpr`, `consteval` 或 `constinit`; 不支持的旧标准使用常量表达式或明确初始化.

6.11 **[推荐]** 临时组合且字段无独立语义时使用 `std::pair` 或 `std::tuple`; 字段有明确含义时定义 `struct`. 不用 pair 的 `.first` / `.second` 表达业务概念.

6.12 **[必须]** 不用 C 风格数组和字符串. 使用 `std::array`, `std::vector`, `std::string`; 数组大小使用 `std::size` 或容器接口.

6.13 **[推荐]** 不手写 `sizeof` 计算数组元素个数. 使用标准库工具, 容器和范围接口.

6.14 **[推荐]** 字符用于算术时明确使用 `signed char` 或 `unsigned char`. 不假设普通 `char` 的有符号性.

## 7. STL, 算法与 Lambda

7.1 **[推荐]** 默认容器 `std::vector`; 固定大小 `std::array`; 有序映射 `std::map` / `std::set`; 哈希映射 `std::unordered_map` / `std::unordered_set`. `std::list` 仅在需要稳定迭代器或频繁中间插入时使用.

7.2 **[必须]** 就地构造使用 `emplace_back` / `emplace`; 已有对象或需要显式转换时 `push_back` 可能更清晰. 已知规模时 `reserve`.

7.3 **[推荐]** 使用迭代器或范围 `for` 遍历容器. 只读使用 `const auto&`, 修改使用 `auto&`; 不修改时优先 `const_iterator`.

7.4 **[必须]** 删除满足条件的元素使用 erase-remove 惯用法. 标准支持时可用 `std::erase_if`. `std::remove` 不删除元素, 必须配合 `erase`.

7.5 **[必须]** `std::map::operator[]` 会插入默认值. 只查找时使用 `find`, `at`; 标准支持时可用 `contains`, 否则使用 `find != end()`. 不假设 `at` 在所有项目错误策略下都合适.

7.6 **[必须]** 比较器满足严格弱序, 使用 `<` 而不是 `<=`. 哈希函数必须与 `operator==` 保持一致.

7.7 **[版本相关]** 优先标准算法 `<algorithm>` / `<numeric>` 替代手写循环. 标准支持时使用 `std::clamp`, `std::size`, `std::as_const`, `std::invoke`, `std::apply`; 不支持时使用项目已有的等价工具.

7.8 **[必须]** Lambda 捕获列表显式写出对象. 避免默认捕获 `[=]` / `[&]`, 尤其在异步, 回调或生命周期延长场景.

7.9 **[必须]** `[this]` 捕获指针, 对象销毁后不得使用. 标准支持时 `[*this]` 捕获对象副本, 注意拷贝代价和状态同步.

7.10 **[推荐]** Lambda 优于 `std::bind`. 通用引用使用 `T&&` 和 `std::forward<T>`.

7.11 **[推荐]** `std::function` 有类型擦除和调用开销; 性能敏感处使用模板, 函数指针或专用接口. `std::vector<bool>` 是位压缩特化, 需要普通 bool 时使用其他容器.

7.12 **[版本相关]** 标准支持时使用结构化绑定解构 pair, tuple 或聚合类型. 范围 `for` 中明确使用 `auto&` / `const auto&` 避免不必要拷贝.

7.13 **[版本相关]** 标准支持时使用嵌套命名空间语法和 inline 变量. 头文件常量优先 `inline constexpr`, 避免 ODR 问题.

7.14 **[必须]** 输出换行使用 `'\n'`, 只有确实需要刷新时才使用 `std::endl`.

7.15 **[推荐]** `std::string_view` 只用于只读借用; 接口需要稳定存储或修改能力时使用 `std::string`. 不返回指向临时字符串的 view.

7.16 **[推荐]** 不在热路径默认使用 `std::regex`, `std::function`, `std::shared_ptr` 或异常控制流. 先用清晰实现, 有测量证据后再优化.

## 8. 并发

8.1 **[推荐]** 优先 `std::async` / `std::future` 表达异步任务. 必须使用线程时, 确保析构前 `join` 或 `detach`; 标准支持时优先 `std::jthread`.

8.2 **[必须]** 使用 `std::atomic`, `std::lock_guard`, `std::unique_lock` 管理同步; 标准支持时多锁优先 `std::scoped_lock`. 避免手动 `lock` / `unlock`.

8.3 **[必须]** 不在持有锁时调用未知代码, IO, 回调或可能阻塞的操作. 多锁使用 `std::scoped_lock` 或固定锁顺序避免死锁.

8.4 **[推荐]** 一次性结果使用 `std::promise` / `std::future`, 不用全局变量轮询. 多次数据传递使用 `std::queue` 加 `std::condition_variable` 构建生产者-消费者模型.

8.5 **[必须]** 条件变量等待使用谓词形式 `wait(lock, predicate)`, 防止虚假唤醒和丢失通知.

8.6 **[必须]** `std::atomic` 默认使用 `memory_order_seq_cst`. 放宽内存序必须有明确理由, 并通过模型或测试证明正确.

8.7 **[必须]** `volatile` 不用于线程同步. 它不提供原子性和内存序保证.

8.8 **[推荐]** 一次性初始化使用 `std::call_once` / `std::once_flag` 或函数局部静态. 依赖标准保证函数局部静态初始化线程安全.

8.9 **[必须]** 明确对象的线程安全契约. `const` 成员函数不自动线程安全; `shared_ptr` 引用计数原子, 但被指向对象的访问不自动线程安全.

8.10 **[版本相关]** 读多写少时可用 `std::shared_mutex` / `std::shared_lock`. 标准不支持时使用项目已有的读写锁抽象.

8.11 **[必须]** 不使用 detach 线程访问可能已销毁的全局或静态对象. 线程生命周期必须与所访问状态的生命周期匹配.

## 9. 错误处理与异常

9.1 **[必须]** 错误处理策略必须与项目一致. 默认允许异常用于错误传播, 但要求 RAII 和异常安全; 不使用异常做正常控制流.

9.2 **[Google/可选]** 项目声明采用 Google 内部模式时, 禁用异常和 RTTI, 使用 `Status`, 错误码或 `optional` 传播错误, 输出参数使用指针. 此模式下资源管理不得依赖异常.

9.3 **[必须]** 同一模块不混用互相冲突的错误模型. 异常, 错误码, `Status` 和 `optional` 的边界必须明确.

9.4 **[必须]** 按 `const` 引用捕获异常. 不 `catch (...)` 吞掉异常; 必须捕获全部异常时, 应记录, 转换或重新抛出.

9.5 **[必须]** 析构函数不抛异常. 移动构造, 移动赋值和 `swap` 应尽量 `noexcept`; `noexcept` 函数内必须处理可能抛出的调用.

9.6 **[版本相关]** `std::optional` 表示缺失值, 不替代详细错误信息. 标准支持时可用 `std::expected` 或项目 `Status` 表达错误和值.

9.7 **[推荐]** `assert` 仅用于内部不变量和程序员错误, 不用于可恢复的运行时错误或外部输入校验.

## 10. 命名

本节是项目 C++ 命名 profile, 参考 `ApplicationLifecycle.h`, 不按 Google C++ 命名规则中的文件名, 函数名和枚举值处理. 跨语言规则见 `../naming-conventions/SKILL.md`.

10.1 **[项目约定]** 名称使用英文, 描述用途而不是实现. 避免不常见缩写和易混淆字符 `l`, `O`, `I`.

10.2 **[项目约定]** 文件名使用 `PascalCase`, 与主类型或主职责一致. 头文件使用 `.h`, 源文件使用 `.cc` 或项目统一扩展名. 测试文件使用 `FooTest.cc`. 不使用 `utils`, `helpers`, `misc` 作为文件名.

10.3 **[项目约定]** 类型, class, struct, enum, using 别名使用 `PascalCase`.

10.4 **[项目约定]** 普通变量, 参数和局部变量使用 `snake_case`; 短生命周期计数器可使用 `i`, `j`, `n`.

10.5 **[项目约定]** 类数据成员使用 `snake_case_`; struct 数据成员使用 `snake_case`, 不加尾随下划线.

10.6 **[项目约定]** 常量使用 `k` 加 `PascalCase`; 枚举值使用 `PascalCase`, 不加 `k` 前缀.

10.7 **[项目约定]** 函数和方法使用 `snake_case`. 访问器直接使用名词, 如 `state()`; 修改器使用 `set_` 前缀, 如 `set_state()`; 布尔谓词使用 `is_` / `has_` / `can_` / `should_`.

10.8 **[项目约定]** 命名空间使用 `snake_case`; 内部实现可使用带库名限定的 `internal` 命名空间.

10.9 **[项目约定]** 类型模板参数使用 `PascalCase`, 常用单字母 `T`, `U`, `V`; 标准支持 concepts 时 concept 名也使用 `PascalCase`.

10.10 **[项目约定]** 宏使用全大写加下划线, 并带项目前缀. 宏仅用于条件编译和头文件守卫, 不用宏定义常量或函数.

10.11 **[项目约定]** 类型别名使用 `PascalCase`. 不使用 `typedef`, 统一使用 `using`.

10.12 **[必须]** 引用标准库, 系统 API 或第三方库名称时保留其原始拼写, 不为满足本项目命名规则而改名.

10.13 **[项目约定]** 文件改名为 `PascalCase` 时, 同步修改 include, 构建脚本, 测试和文档. Windows 上做仅大小写改名时先改成临时名, 再改成目标名.

## 11. 注释

11.1 **[推荐]** 注释解释为什么, 约束, 不变量和反直觉行为, 不复述代码表面动作. 优先使用 `//`; 块注释只用于确实需要跨行说明的场景.

11.2 **[Google]** 文件顶部说明文件职责, 必要时包含法律声明. 不写无维护价值的作者, 日期和修改记录.

11.3 **[推荐]** 公共类说明其职责, 不变量, 生命周期和线程安全. 公共函数说明前置条件, 后置条件, 所有权, 失败方式和副作用.

11.4 **[必须]** 所有权转移, 借用生命周期, 锁要求和特殊错误语义必须在使用点留下注释.

11.5 **[必须]** TODO 注释写明负责人或追踪项, 推荐格式 `TODO(name): 原因和后续动作`. 没有负责人和上下文的 TODO 不允许提交.

11.6 **[必须]** 注释标点和拼写必须正确. 注释与代码同时维护, 过期注释比没有注释更危险.

11.7 **[必须]** 不保留注释掉的代码. 历史由版本控制保存; 需要示例时使用最小可编译片段并说明用途.

11.8 **[推荐]** 实现细节注释放在相关代码附近. 文件级大段说明只保留对理解整体设计必要的信息.

## 12. 格式

12.1 **[必须]** 格式以项目 `.clang-format` 为准. 若项目未配置, 使用 Google 基线.

12.2 **[Google]** 行宽 80 列, 缩进 2 个空格, 不使用制表符. 长表达式在语义边界换行, 不为了凑行宽破坏可读性.

12.3 **[必须]** 控制语句和函数使用大括号, 即使只有一条语句. 左大括号与语句同行, 命名空间内容不缩进.

12.4 **[Google]** 指针和引用符号靠近类型, 例如 `int* value`, `const std::string& name`. 项目已有风格不同则统一遵循项目风格.

12.5 **[必须]** include 分组之间空一行, 组内按字母排序. 不使用多个连续空行.

12.6 **[Google]** 构造函数初始化列表可以放在同一行时放同一行; 需要换行时每项一行, 逗号在前或在后必须全项目统一.

12.7 **[必须]** 一行只写一条语句. 不在同一行声明多个变量. 不使用尾随空白, 文件末尾保留一个换行.

12.8 **[Google]** 浮点字面量必须有明确小数点和指数形式, 需要时使用 `f` / `l` 后缀, 避免整数除法或隐式精度变化.

12.9 **[推荐]** Lambda 捕获列表, 参数列表和函数体按项目格式换行. 过长 Lambda 提取为具名函数或函数对象.

12.10 **[必须]** 预处理指令从行首开始, 嵌套条件编译保持可追踪的缩进和结束注释. 不使用宏生成难以调试的控制流.

## 13. Google 常用约定速查

以下条目是 Google C++ Style 中最常影响代码生成和审查的部分, 正文已在相关章节展开.

- 头文件自包含, Include What You Use, 不依赖传递包含.
- 前向声明只用于本项目类型, 不声明 `std` 或第三方实体.
- 禁止 `using namespace` 和 inline namespace.
- 避免非平凡析构的静态对象和静态智能指针.
- `struct` 只做被动数据载体, 其他类型用 `class`.
- 单参数构造和转换运算符默认 `explicit`.
- 公共 API 明确拷贝和移动语义, 避免切片.
- 优先返回值, 输入参数在输出参数之前.
- 不重载 `&&`, `||`, `,`, 一元 `&`, 不定义用户自定义字面量.
- 文件名 `PascalCase`, 类数据成员尾随 `_`, struct 数据成员不尾随 `_`.
- 函数和方法 `snake_case`, 变量 `snake_case`, 常量 `kPascalCase`, 枚举值 `PascalCase`.
- 注释解释意图, TODO 必须有负责人或追踪项.
- Google 格式化基线为 80 列, 2 空格, 无制表符.
- 项目采用 Google 内部模式时禁用异常和 RTTI, 否则按项目错误策略执行.

## 14. 明确避免

- **标准不匹配**: 使用高于项目标准的语言或库特性, 依赖未确认的编译器扩展.
- **头文件问题**: 非自包含头文件, 传递包含, 头文件中 `using namespace`, 在 `std` 中声明实体.
- **资源问题**: 裸 `new` / `delete`, 同一裸指针构造多个智能指针, 返回局部引用, `return std::move(local)`.
- **对象安全问题**: 构造或析构中调用虚函数, 非虚析构的多态基类, 对象切片, 悬空 view.
- **初始化问题**: 未初始化内置类型, 窄化转换, 构造初始化顺序与声明顺序不一致.
- **类型问题**: C 风格转换, `NULL`, C 风格数组和字符串, 有符号无符号混用, 未定义行为.
- **C 接口问题**: `rand()`, `atoi`, `sprintf` 到固定缓冲区, 以及优先使用 C 头文件而不是对应 C++ 设施的写法.
- **STL 问题**: `map::operator[]` 误用, `remove` 后不 `erase`, 比较器不满足严格弱序, 默认 Lambda 捕获跨生命周期.
- **并发问题**: 手动 lock/unlock, 条件变量不带谓词, `volatile` 做同步, detach 线程访问已销毁状态.
- **错误处理问题**: `catch (...)` 吞异常, 析构抛异常, `noexcept` 中放任异常, 忽略必须处理的返回值.
- **接口问题**: 隐式转换, 未说明所有权, 未说明线程安全, 用输出参数替代清晰返回值.
- **维护问题**: 注释掉的代码, 无负责人 TODO, 过期注释, 与项目格式和命名不一致.
- **废弃特性**: `std::auto_ptr`, `std::random_shuffle`, `std::bind1st` / `std::bind2nd`, `std::ptr_fun` / `std::mem_fun`, `std::unary_function` / `std::binary_function`, `std::iterator` 基类, 动态异常说明, `register`, 已废弃的 C 兼容头文件.
- **控制流问题**: `goto` 除跳出多层循环且明显更清晰外不使用; 不用异常, 宏或复杂表达式隐藏正常控制流.

## 15. 快速审查清单

生成或修改代码后逐项自检:

- [ ] 是否确认了项目语言标准, 且未使用超出标准的特性?
- [ ] 是否遵循项目现有构建配置, 命名, 格式和错误处理策略?
- [ ] 头文件是否自包含, include 顺序正确, 没有传递包含依赖?
- [ ] 是否存在裸 `new` / `delete`, 所有权是否清晰?
- [ ] 是否优先值语义, `unique_ptr`, 最后才是 `shared_ptr`?
- [ ] 是否正确处理 Rule of Zero/Five, 移动语义和 `noexcept`?
- [ ] 是否初始化所有内置类型, 避免窄化和未定义行为?
- [ ] 多态基类析构是否 `virtual` 或 protected, 覆盖是否 `override`?
- [ ] 单参数构造和转换运算符是否按语义使用 `explicit`?
- [ ] 是否存在对象切片, 隐式转换, 悬空引用或悬空 view?
- [ ] 函数参数顺序是否清晰, 输出参数是否可辨认?
- [ ] 容器选择, 遍历, 删除, 查找和比较器是否正确?
- [ ] Lambda 捕获是否显式, 是否存在生命周期风险?
- [ ] 并发是否使用 RAII 锁, 条件变量是否谓词等待, 线程是否可连接?
- [ ] 异常策略是否与项目一致, 是否保证异常安全?
- [ ] 命名, 注释, 格式是否符合项目或 Google 基线?
- [ ] 是否引入无依据的优化, 复杂模板或不必要抽象?
- [ ] 是否清理了调试代码, 注释代码和无上下文 TODO?

审查输出建议按严重程度分组:

- **错误**: 会导致未定义行为, 数据竞争, 资源泄漏, 安全漏洞或编译失败.
- **风险**: 可能引发生命周期, 异常安全, 性能或可维护性问题.
- **建议**: 风格, 可读性和局部现代化改进.

每条问题给出 `文件:行号`, 具体原因和最小修复方案. 不做与任务无关的大范围风格改写.
